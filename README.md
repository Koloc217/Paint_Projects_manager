# RPi5 Project Hub

**Русский** · [English](README.en.md)

Локальный трекер хобби-проектов (3D-печать и покраска миниатюр) для Raspberry Pi 5.
Веб-интерфейс, Telegram-бот, уведомления по расписанию и система «токенов»: новый проект стоит токены,
завершённый приносит награду. Идея в том, чтобы не бросать начатое и не копить нераскрашенные модели.

> Статус: личный проект «для себя». Работает на одном пользователе, данные хранятся локально.

## Что умеет

**Проекты и задачи**
- Карточки проектов: статус, стадия (печать, шлифовка, сборка, грунт, покрас, доводка), приоритет, срок, фото.
- Поиск проектов в списке активных и в Зале славы: по названию, номеру, статусу, стадии, заметкам и названиям задач.
- Задачи с дедлайнами, статусами, переносом срока и редактированием.
- Доска позора: счётчик переносов сроков (кнопка «+2 дня» в боте и более поздняя дата в веб-редакторе; отпуск не
  считается). Значок ⏳×N у задачи, блок в аналитике (всего, за 30 дней, рекордсмены), строка в пятничной и месячной
  сводке. Только текст, токены не отнимаются.
- Общие задачи без проекта: разобрать полки с красками, обслужить аэрограф и прочее, что не относится к модели.
  Создаются в том же окне «+ Задача» (пункт «Без проекта»), идут отдельной группой во «Всех задачах», попадают в
  календарь, сводки, отпуск и на фоторамку; токенов и стадий у них нет, дедлайн необязателен.
- Референсы: изображения к проекту с просмотром на весь экран.
- Фото прогресса: снимки по ходу работы с датой и стадией, лента времени в карточке проекта и общая вкладка «Лента».
- Журнал действий на вкладке «Лента»: по дням, что происходило с проектами и задачами (статусы, стадии, новые и
  закрытые задачи, переносы сроков), из веба и из бота.
- Корзина: удалённый проект 30 дней лежит в корзине и его можно вернуть.
- Календарь дедлайнов: месяц сеткой со сроками задач и проектов.
- Сроки в календарь телефона (опция, по умолчанию выключена: Настройки → Основные → «Сроки в календарь телефона»):
  файлом `.ics` (кнопка «В телефон» на вкладке «Календарь» или `/calendar` в боте) или подпиской, которая обновляется сама.
- Заметки по проекту прямо в карточке: рецепты красок, пропорции, идеи, что угодно.
- Шаблоны пайплайна: по умолчанию «3D-печать» (7 этапов) и «сборная модель» (5 этапов), в настройках их можно
  править и добавлять свои. Перед созданием открывается окно сроков: у каждого этапа своя дата, этап можно пропустить,
  а сроки можно распределить равномерно до даты проекта. Этапы, которые уже есть в проекте, повторно не создаются.
- Отпуск: до 30 дней без уведомлений, сроки незавершённых проектов и задач сдвигаются на тот же срок.
- Затраченное время (необязательно): у задачи при редактировании (`90`, `1:30`, `1.5ч`, `1ч 30м`) и у проекта
  «вне задач». В карточке проекта: «предположительно ~N ч», для скольких задач время указано и разбивка по стадиям.
  На токены не влияет.

**Токены и мотивация**
- Баланс токенов: старт проекта стоит токены, завершение даёт награду.
- Зал славы: завершённые проекты, статистика и графики (воронка по стадиям, закрытые задачи и проекты за 6 месяцев).
- DEV MODE для тестов и правок баланса.

**Telegram-бот**
- Привязка к одному чату по коду, бот отвечает только привязанному чату.
- Команды и кнопки: список проектов, текущая задача, закрытие и перенос задач, смена статуса и стадии.
- `/help` показывает все команды и возможности. `/task` (или кнопка «Задача») создаёт задачу по шагам: проект (или «Без проекта»), название, срок. `/general` (или кнопка «Общие») — общие задачи с кнопками «В работу» и «Готово».
- После закрытия задачи бот спрашивает, сколько она заняла: кнопки 15 мин…2 ч, своё значение или «Пропустить»
  (выключается в Настройки → Telegram).
- `/calendar` присылает сроки файлом `.ics` для календаря телефона (если выгрузка в календарь включена в настройках).
- Фото: пришли боту снимок (подпись станет заметкой), и он попадёт в ленту проекта. `/photo` показывает последние фото и листает их.
  `/myphotos`: выбираешь проект, потом фото прогресса или референсы покраса. Если фото не сохранилось, бот об этом напишет.
- Вечерняя сводка, пятничный дайджест, отчёт за месяц, предупреждение о застое проекта. `/summary` присылает сводку сразу,
  не дожидаясь расписания.
- Чат не захламляется: старые сводки удаляются сами (последняя остаётся, режим в Настройки → Telegram), `/clear` убирает
  весь чат за последние 48 часов (раньше Telegram боту удалять не даёт).
- Расписание по дням недели настраивается в интерфейсе.

**Оформление и язык**
- Стандартная тема и восемь дополнительных: Cyberpunk, Hammer, SCP Dossier, Workbench, Synthwave, JRPG (FFVII),
  Model Manual, Hardware PCB. Графики подхватывают цвета темы. Как добавить свою: [THEMES_GUIDE.md](docs/THEMES_GUIDE.md).
- Язык интерфейса, бота и уведомлений: русский и английский. Все тексты лежат в одном файле `locales.json`.
- Формат дат с годом на выбор: `21.03.2027` или `03/21/2027`.
- Телефонная вёрстка (вкладки внизу экрана) и установка на главный экран как приложение (PWA), см. раздел «Телефон».

**Безопасность**
- Необязательный вход по паролю, по умолчанию выключен. Включается в Настройки → Доступ.
  Первый вход под `admin` / `123456`, потом система требует сменить пароль.
- Пароль не передаётся открытым текстом (клиент отправляет хэш, сервер хранит scrypt).
- HTTPS в базовом варианте: строка `HTTPS=1` в `.env` включает шифрование, сертификат создаётся сам
  (см. раздел «HTTPS» ниже). Без HTTPS перехваченный хэш можно переслать повторно, поэтому в сеть интернета
  приложение без него выставлять нельзя.

**Резервные копии и надёжность**
- Архив с данными: Настройки → Бэкап → «Скачать архив» — база, настройки и все фото одним zip-файлом.
  Восстановление там же («Восстановить из архива») или из консоли: `python tools/archive_tool.py restore архив.zip`.
  Пароль входа, `.env` и сертификаты в архив не попадают.
- Если приложение было выключено во время пуша, после запуска пропущенный запуск выполняется сам.
- База SQLite в режиме WAL: веб, бот и скрипты пишут в неё одновременно без блокировок.
- Версионированные миграции схемы (`hub/core/migrations.py`, версия в `PRAGMA user_version`): каждый шаг выполняется один раз,
  в транзакции; перед миграцией копия базы сохраняется в `backups/tracker-before-v<N>-<дата>.db` (5 последних).
- Внешние ключи: задачи, референсы и фото прогресса не могут ссылаться на несуществующий проект.
- Фото, на которые не ссылается ни одна запись, раз в 6 часов переносятся в `orphans/<дата>/` и удаляются через 30 дней
  (файлы моложе часа и чужие файлы не трогаются, фото проектов в корзине сохраняются).
- Проверка восстановления: `python tools/check_backup.py` (см. «Проверки»).

**Архив: перенос на другой сервер и восстановление**

```
python tools/archive_tool.py create                  # project-hub-<дата>.zip в текущей папке (то же, что кнопка в настройках)
python tools/archive_tool.py check   архив.zip       # проверить архив, ничего не меняя
python tools/archive_tool.py restore архив.zip       # заменить базу и настройки, добавить фото
python tools/archive_tool.py restore архив.zip --no-config   # оставить текущий config.json
```

Восстановление сначала проверяет архив (manifest, пути внутри, целостность базы) и ничего не трогает, если что-то
не так. Текущая база сохраняется в `backups/tracker-before-restore-<дата>.db` (3 последних). Архив от старой версии
приложения подходит (база доводится миграциями), от более новой — нет. Фото, которых нет в архиве, не удаляются сразу:
их уберёт обычная проверка в `orphans/`. На новом сервере: установить приложение, восстановить архив, настроить `.env`
(токен бота) и запустить.

## Стек

Python 3.10+, FastAPI, SQLAlchemy + SQLite, Jinja2, httpx, Tailwind, Chart.js, Telegram Bot API.

Интерфейс не зависит от интернета: Tailwind CSS, Chart.js и шрифты тем лежат в `static/vendor/` и `static/fonts/`.
После новых классов Tailwind в шаблонах или JS: `python tools/build_assets.py css` (нужен Node.js, только там, где собираете).

## Запуск

```bash
git clone https://github.com/Koloc217/Paint_Projects_manager.git
cd Paint_Projects_manager
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env          # впишите TELEGRAM_BOT_TOKEN
python app.py                 # веб, бот и планировщик одним процессом
```

Интерфейс откроется на `http://<адрес устройства>:8000`. Файлы `tracker.db`, `config.json`, `auth.json`
и папка `photos/` создаются при первом запуске и в git не попадают.

### Порт и адрес

Порт по умолчанию 8000. Если он занят или нужен другой, впишите его в `.env` и перезапустите приложение:

```
PORT=8080
HOST=0.0.0.0        # необязательно: 0.0.0.0 — доступ из всей сети (по умолчанию), 127.0.0.1 — только с этого компьютера
```

Для одного запуска можно без `.env`: `python app.py --port 8080` (и `--host 127.0.0.1`); ключи важнее `.env`.
При старте в консоли печатается, на каком адресе и порту приложение слушает. Порт один для HTTP и HTTPS.
Если приложение запущено как systemd-сервис, порт тоже берётся из `.env`: правка `ExecStart` не нужна, только
`sudo systemctl restart tracker`. `tools/deploy.sh` читает `PORT` из того же `.env`.

Привязка бота: Настройки → Telegram, получить код и отправить его боту в нужном чате.

Прокси для Telegram не обязателен. Если Telegram недоступен напрямую, включите его там же (Настройки → Telegram →
«Прокси для Telegram»): SOCKS5 или HTTP, кнопка «Проверить связь», применяется без перезапуска.
Старый способ тоже работает: `PROXY_URL` в `.env` действует, пока прокси не настроен в приложении.

## Обновление на устройстве

Если приложение стоит как git-клон и работает как systemd-сервис, свежую версию любой ветки выкладывает одна команда:

```bash
tools/deploy.sh                          # main
tools/deploy.sh feature/имя-ветки        # проверить ветку до слияния
tools/deploy.sh --rollback               # вернуть то, что стояло до последней выкладки
```

Скрипт делает копию базы в `backups/` (хранит 10 последних), берёт ветку из GitHub, ставит зависимости, если
поменялся `requirements.txt`, перезапускает сервис и проверяет, что сервер отвечает. Данные (`tracker.db`, `photos/`,
`config.json`, `.env`) не трогаются. Если в файлах проекта есть ручные правки, скрипт остановится.
Настройки через переменные: `VENV` (путь к venv), `SERVICE` (по умолчанию `tracker`), `PORT` (по умолчанию из `.env`, иначе 8000).
Остатки старых версий (файлы вне git и вне `.gitignore`) убирает `tools/clean.sh`: показывает список и после
подтверждения переносит их в соседнюю папку `<проект>-leftovers-<дата>`.
Скрипты только для Linux с systemd; на Windows обновление вручную: `git pull` и перезапуск.

## HTTPS

По умолчанию приложение работает по обычному HTTP. Чтобы включить шифрование, добавьте в `.env`:

```
HTTPS=1
```

и перезапустите приложение. При первом запуске само создаётся самоподписанный сертификат
(`certs/server.crt` и `certs/server.key`, срок 825 дней). В него входят `localhost`, имя и адрес устройства в сети
и всё, что перечислено в `TLS_NAMES` (например `TLS_NAMES=hub.local,192.168.1.50`). Порт остаётся прежним
(`PORT` в `.env`, по умолчанию 8000, см. «Порт и адрес»), только адрес теперь начинается с `https://`. Нужна утилита `openssl`
(на Raspberry Pi OS есть).

- **Предупреждение браузера.** Сертификат самоподписанный, поэтому на каждом устройстве один раз появится
  «соединение не защищено». Нажмите «Дополнительно → Перейти на сайт». Чтобы предупреждение исчезло, добавьте
  `certs/server.crt` в доверенные сертификаты устройства.
- **Если адрес устройства поменялся**, пересоздайте сертификат: `python -m hub.web.tls cert --force`
  (или добавьте новый адрес в `TLS_NAMES`).
- **Свой сертификат** (например, от mkcert или Let's Encrypt): укажите оба пути, `SSL_CERTFILE` и `SSL_KEYFILE`.
- **Проверка:** `python -m hub.web.tls status` показывает режим, порт и сколько дней осталось у сертификата.
  Во вкладке «Доступ» в настройках видно, по какому соединению открыта страница.
- Ключ `certs/server.key` никому не передавайте, папка `certs/` в git не попадает.

## Телефон

На экране уже 640 px страница перестраивается: вкладки уходят в нижнюю панель, шапка становится двухстрочной
(логотип, тема, настройки и токены сверху, «+ Проект» и «+ Задача» снизу), строки задач складываются в столбик,
окна занимают почти весь экран. Кнопки «изменить» и «удалить», которые на компьютере видны при наведении мыши,
на сенсорных экранах видны всегда. Стили лежат в `static/mobile.css` и на десктопе ничего не меняют.

**Установка на главный экран (PWA).** Подсказка для текущего браузера: Настройки → Основные → «Приложение на телефоне».

- **iPhone и iPad (Safari):** «Поделиться» → «На экран „Домой“». Страница откроется без адресной строки.
- **Android (Chrome):** если страница открыта по доверенному HTTPS, в настройках появится кнопка «Установить»
  (или Chrome сам предложит установку). Иначе: меню ⋮ → «Добавить на главный экран».

**Что зависит от HTTPS.** Service worker (офлайн-заглушка «Нет связи», кэш файлов интерфейса, полноценная установка в
Chrome) браузер включает только на `https` с сертификатом, которому устройство доверяет, или на `localhost`.
По обычному `http` в домашней сети значок добавить можно, но в Android это будет ярлык, открывающийся во вкладке
браузера. Чтобы телефон доверял сертификату:

- самый надёжный путь: сертификат от [mkcert](https://github.com/FiloSottile/mkcert) (`SSL_CERTFILE`, `SSL_KEYFILE`
  в `.env`), а его корневой сертификат `rootCA.pem` установить на телефон
  (Android: Настройки → Безопасность → Шифрование и учётные данные → Установить сертификат → Сертификат ЦС;
  iPhone: открыть файл, установить профиль, затем Основные → Об этом устройстве → Доверие сертификатам);
- самоподписанный `certs/server.crt` iPhone принимает так же (профиль + доверие), Android может отказаться
  ставить его как сертификат ЦС.

Данные проектов не кэшируются: всё берётся с сервера, без связи показывается заглушка с кнопкой «Повторить».
Файлы приложения сначала запрашиваются с сервера, поэтому после обновления новые версии приходят сразу.
Вход по паролю установке не мешает: `/sw.js` и `/manifest.webmanifest` открыты без входа.

## Внешние устройства

Для фоторамки на e-ink и других экранов (ESP32 и т. п.) есть отдельный API `/api/v1/`. Приложение только отдаёт
данные, вёрстку (шрифт, цвета, обрезку длинных названий под свою ширину) делает само устройство.
По умолчанию выключено, включается в `config.json`:

```json
"DEVICE_API": {"enabled": true, "key": "", "hot_days": 3}
```

- `enabled`: без него `/api/v1/` отвечает 404;
- `key`: необязательный ключ. Если задан, устройство передаёт его заголовком `X-Device-Key` или `?key=...`.
  При включённом входе по паролю ключ обязателен: без него `/api/v1/` закрыт;
- `hot_days`: задача с дедлайном в ближайшие столько дней (или просроченная) считается горящей.

**`GET /api/v1/hot?limit=2`**: что показать на маленьком экране.

1. Горящие задачи: сначала просроченные (самые старые), потом с близким дедлайном, не больше `limit` (до 5).
2. Горящих нет: одна ближайшая задача с дедлайном, даже если срок далеко.
3. Задач с дедлайном нет: пустой список и готовая фраза на языке приложения.

Задачи без дедлайна не учитываются. Закрытые задачи, законченные и приостановленные проекты и корзина не попадают.

```json
{"mode": "hot", "today": "2026-11-03", "message": "",
 "tasks": [{"id": "TSK-…", "name": "Грунт", "project": "Рыцарь", "project_id": "PRJ-…",
            "deadline": "2026-11-02", "days_left": -1, "overdue": true}]}
```

`mode`: `hot` | `nearest` | `empty`; `message` заполнен только для `empty`. Пример для рамки:
`curl -s http://<адрес-pi>:8000/api/v1/hot -H "X-Device-Key: <ключ>"`.

## Проверки

```bash
python tools/check_locales.py      # ключи переводов: что используется, что пропущено
python tools/check_theme.py        # все темы из реестра (или одна: theme-имя)
python tools/build_assets.py css   # пересобрать Tailwind CSS после новых классов (без css: ещё шрифты и Chart.js)
python tools/check_backup.py       # восстанавливается ли последняя копия из backups/ (или: check_backup.py ФАЙЛ)
python tools/check_data.py         # записи без проекта, фото без файла, файлы без записи (--fix: в orphans/)
python tools/make_thumbs.py        # один раз: превью для старых обложек и старых фото из Telegram (нужен pillow)
```

`check_backup.py` ничего не меняет: копирует бэкап во временную папку, проверяет файл SQLite, прогоняет миграции
на копии, читает её моделями приложения и сравнивает числа с текущей базой. Чтобы восстановить прошедшую проверку
копию: остановить приложение, положить файл вместо `tracker.db` (и удалить `tracker.db-wal`, `tracker.db-shm`), запустить.
Архив целиком проверяется отдельно: `python tools/archive_tool.py check архив.zip`.

Кэш в браузере: страницы ссылаются на `/static/файл?v=<метка>`, такие файлы и фото (`/photos/...`, у каждой загрузки
новое имя) браузер хранит год и не перезапрашивает; после обновления приложения метка меняется сама.

### Тесты

```bash
pip install -r requirements-dev.txt   # один раз: pytest
python -m pytest                      # все тесты, около 2 секунд
python -m pytest tests/test_tasks.py  # один файл
```

Тесты работают с пустой временной папкой данных (`PROJECT_HUB_DATA_DIR`): настоящие `tracker.db`,
`config.json`, фото и `.env` (токен бота) они не видят и не меняют. Что покрыто: проекты и токены, задачи, корзина, шаблоны пайплайна,
коды статусов и миграция старых значений, полнота переводов, отпуск, догон пропущенных запусков,
баланс токенов через корзину и переоткрытие, проверка `config.json`, все команды бота на подменённом Telegram.

Проверка миграции на копии своей базы (сам файл не меняется):

```bash
PROJECT_HUB_TEST_DB=/путь/к/tracker.db python -m pytest tests/test_real_db.py
```

В PowerShell: `$env:PROJECT_HUB_TEST_DB="C:\путь\tracker.db"; python -m pytest tests/test_real_db.py`.

### Папка данных и IDE

Все данные (`tracker.db`, `config.json`, `.env`, `auth.json`, `photos/`, `logs/`) лежат рядом с кодом. Переменная
окружения `PROJECT_HUB_DATA_DIR` переносит их в другую папку; так делают тесты и запуск из IDE.
`tools/deploy.sh` рассчитан на данные рядом с кодом.

IntelliJ IDEA (с плагином Python) или PyCharm: File → Open → папка проекта, указать интерпретатор Python
(Settings → Project → Python Interpreter, лучше отдельный venv) и выполнить `pip install -r requirements-dev.txt`.
В списке запуска появятся две общие конфигурации из папки `.run/`:

- **Tests: all** — все тесты, с отладкой (точки останова в коде срабатывают);
- **Project Hub (dev data)** — приложение на отдельных данных в `.devdata/`. Там нет `.env`, поэтому бот
  не запускается и не мешает рабочему боту на Pi.

## Известные ограничения

- Один пользователь, без ролей и прав.
- HTTPS по умолчанию выключен, а сертификат самоподписанный: шифрование есть, но каждое устройство один раз
  покажет предупреждение. Автоматического продления сертификата нет.
- Перенаправления с HTTP на HTTPS нет: порт один, и на нём работает либо HTTP, либо HTTPS.
- Архив делается только вручную (кнопкой или скриптом), по расписанию его нет.
- PWA без доверенного HTTPS работает урезанно (ярлык вместо приложения, без офлайн-заглушки).
- Догон пропущенных запусков ограничен: пуши в пределах 3 часов того же дня, только последний запуск.
- База в режиме WAL: файл `tracker.db` на ходу копировать нельзя (остановите приложение или используйте `sqlite3 tracker.db ".backup копия.db"`).
- Названия задач из шаблона сохраняются на языке, который был активен при создании.
