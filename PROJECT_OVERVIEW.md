# RPi5 Project Hub — логика и функциональность

**Русский** · [English](PROJECT_OVERVIEW.en.md)

Локальный трекер хобби-проектов (3D-печать и покраска миниатюр) для Raspberry Pi 5.
Это веб-приложение с Telegram-ботом, уведомлениями и системой «токенов»: за завершённые проекты
начисляется награда, а новый проект стоит токены. Цель — не бросать начатое и не копить нераскрашенные модели.

---

## 1. Состав и устройство

```
                   ┌────────────────────────── один процесс: python app.py (uvicorn, порт 8000) ──┐
 Браузер ───────►  │  FastAPI (app.py)  ── REST API + страница                                     │
                   │  Бот (bot.py)      ── long polling Telegram (напрямую или через прокси)       │
                   │  Планировщик (scheduler.py) ── раз в 20 с проверяет расписание                │
                   └───────────┬───────────────────────────────┬───────────────────────────────────┘
                               │                               │ по расписанию, отдельным процессом
                  SQLite tracker.db + photos/          notify.py (пуши)   backup.py (бэкап)
                  config.json (настройки, привязка)            │                    │
                                                         Telegram Bot API    Google Apps Script
```

- **Один сервис.** Веб, бот и планировщик запускаются вместе при старте приложения (`lifespan` в `app.py`).
- **Скрипты `notify.py` и `backup.py`** запускаются планировщиком отдельными процессами тем же интерпретатором
  (`sys.executable`), поэтому путь к venv нигде не прописан. Их вывод пишется в `logs/notify.log` и `logs/backup.log`
  (ротация при 1 МБ, три копии, таймаут задачи 180 с). Всё, что приложение печатает в консоль, дублируется в `logs/app.log`
  с той же ротацией (`logs.py`, средствами Python, поэтому одинаково в Windows и Linux).
- **Данные.** `tracker.db` (SQLite), папка `photos/` (фото и референсы), `config.json` (настройки и привязка чата),
  `.env` (секреты).

## 2. Модель данных

SQLite, таблицы создаются автоматически; недостающие колонки добавляются `ensure_schema()` без потери данных.
Внешних ключей нет, связи по строковым ID; при стирании проекта из корзины задачи и файлы удаляются в коде.
У `projects` есть `deleted_at` (не пусто: проект в корзине). Индексы на `tasks.project_id` и `projects.deleted_at`
`ensure_schema()` создаёт и в старых базах (`CREATE INDEX IF NOT EXISTS`).

**`projects`**

| Поле | Смысл |
|---|---|
| `id` | `PRJ-XXXXXX` |
| `name` | название (до 120 символов, не пустое) |
| `status` | `В планах`, `В работе`, `На паузе`, `Закончен` |
| `stage` | `—`, `Печать`, `Шлифовка`, `Сборка`, `Грунт`, `Покрас`, `Доводка` (последние штрихи перед завершением) |
| `priority` | `Low`, `Medium`, `High`, `Critical` |
| `estimate` | дедлайн проекта |
| `token` | сколько токенов потрачено на старт (в DEV MODE 0), целое число |
| `token_reward` | награда за завершение, целое число; видна только на карточке проекта в списке |
| `paint_notes` | заметки по проекту (рецепты красок и всё остальное) |
| `photo` | имя файла фото в `photos/` |
| `updated_at` | последнее «движение» по проекту (для детектора застоя) |
| `completed_at` | когда проект завершён |

**`tasks`**: `id` (`TSK-XXXXXX`), `project_id`, `task_name`, `deadline`, `status` (`Не начато`, `В процессе`, `Закончен`),
`postponed` (сколько раз переносили дедлайн из бота), `completed_at`, `closed_from` (статус до автоматического закрытия
вместе с проектом; пусто, если задачу закрыли вручную).

**`project_refs`** — референсы покраса: `project_id`, `filename` (оригинал), `thumb` (превью), `position` (порядок в карточке), `created_at`.

**`progress_photos`** — фото прогресса (WIP): `project_id`, `filename`, `thumb`, `stage` (стадия проекта в момент загрузки),
`note` (подпись), `source` (`web` или `telegram`), `created_at`. Файлы лежат в `photos/progress/`.

**`adjustments`** — корректировки баланса (удалённые проекты): `amount`, `reason`, `created_at`.

**`activity`** — журнал действий: `created_at`, `project_id`, `project_name`, `task_id`, `task_name` (имена на момент
события), `kind`, `old`, `new`, `source` (`web`, `bot`, `history`).

**`tg_messages`** — сообщения в чате бота, которые можно удалить (`/clear`, уборка сводок): `chat_id`, `message_id`,
`kind` (`bot`, `user`, `digest`, `report`), `created_at`. Записи старше 48 часов стираются, кроме последней сводки.

Статусы и стадии хранятся по-русски и служат значениями в логике; при показе они переводятся на язык интерфейса.
«Завершённым» считается статус `закончен`, `завершено`, `завершен` или `completed` (без учёта регистра).

## 3. Токены и жизненный цикл проекта

**Баланс** = `INITIAL_TOKENS` + награды завершённых проектов − стоимость старта всех проектов + корректировки.

Токены — целые числа: награда и стоимость старта принимаются только целыми от 0 до 1 000 000 (дроби, NaN и
Infinity отклоняются), старые дробные значения в базе один раз округляются при запуске.

- **Создание проекта.** Если DEV MODE выключен и баланса меньше `PROJECT_COST`, проект не создаётся (ошибка с текущим
  балансом). Иначе в проект записывается `token = PROJECT_COST` (в DEV MODE — 0).
- **Награда** засчитывается, когда проект получает статус «Закончен».
- **Завершение проекта.** Если у проекта есть открытые задачи, интерфейс сначала спрашивает подтверждение. Проставляется
  `completed_at`, все открытые задачи становятся «Закончен» с текущей датой, а их прежний статус запоминается в
  `closed_from`. Задачи, закрытые раньше, сохраняют свою дату закрытия, поэтому графики аналитики не сдвигаются.
  Повторная установка того же статуса дату завершения не меняет. Возврат в работу (из Зала Славы или из списка
  статусов) сбрасывает `completed_at` и снова открывает задачи, закрытые вместе с проектом, с их прежним статусом;
  задачи, закрытые вручную, остаются закрытыми.
- **Удаление проекта = корзина.** Проект получает `deleted_at` и пропадает из списков, бота, уведомлений, бэкапа и ленты
  фото; задачи, фото и референсы остаются на месте. Из корзины проект можно вернуть, стереть сразу или подождать:
  через `TRASH_DAYS` дней (по умолчанию 30) его стирает фоновая проверка (при старте и раз в 6 часов). Задачу в проект из
  корзины добавить нельзя.
- **Баланс и корзина.** При `DELETE_KEEPS_BALANCE = true` (по умолчанию) баланс не меняется ни в корзине, ни после стирания:
  при стирании вклад проекта (награда, если он завершён, минус стоимость старта) фиксируется записью в `adjustments`.
  Если опция выключена, стоимость старта возвращается сразу при удалении в корзину и снова вычитается при возврате.
- **Редактирование.** Название и приоритет можно менять всегда. Дедлайн проекта — только в DEV MODE.
- **Что считается «движением» проекта** (`updated_at`): смена статуса и стадии, создание задачи, смена статуса задачи,
  изменение текста в заметках (сохранение без правок не считается), шаблон пайплайна, закрытие или перенос
  задачи из бота, правка в DEV MODE.
  Переименование, смена приоритета, фото и референсы движением не считаются.

### DEV MODE
Один переключатель делает три вещи: отключает автоматические пуши («тихий режим»), разрешает редактировать
дедлайн проекта и позволяет создавать проекты без токенов.

## 4. Веб-интерфейс

### Вкладки
- **Дашборд.** Слева активные проекты карточками, справа «Ближайшие задачи» (5 незавершённых задач с самыми ранними
  дедлайнами, задачи без даты в конце).
  - **Поиск проектов:** строка над списком. Несколько слов через пробел, должны встретиться все. Регистр и ё/е не
    важны. Ищет по названию, номеру, приоритету, статусу, стадии (и по русскому значению, и по переводу на язык
    интерфейса), тексту заметок и названиям задач проекта. Счётчик показывает «найдено / всего», Esc очищает поле,
    фильтр сохраняется при автообновлении данных. Работает на стороне браузера, на сервер ничего не уходит.
- **Все задачи.** Задачи, сгруппированные по активным проектам.
- **Календарь.** Месяц сеткой (при формате дат `mdy` неделя с воскресенья, иначе с понедельника): сроки незавершённых задач
  и 📌 сроки проектов. Просроченное красным, закрытое зачёркнуто, в клетке видно три записи и «ещё N».
  Клик по дню открывает список, клик по записи открывает проект. Завершённые проекты не показываются.
  **Выгрузка на устройства** (`ics.py`) — опция `CALENDAR_EXPORT`, по умолчанию выключена, включается в
  Настройки → Основные → «Сроки в календарь телефона». Пока она выключена, кнопки «В телефон» нет, `/calendar`
  пропадает из меню и `/help` бота, файл и подписка отвечают 404; сама вкладка работает всегда. Токен подписки при
  выключении сохраняется, после включения старый адрес снова работает. Кнопка «В телефон» отдаёт те же сроки
  календарю телефона, без закрытых задач:
  - **файл `.ics`** (кнопка «Скачать .ics» или `/calendar` в боте): снимок на сегодня, импортируется один раз;
  - **подписка** `/cal/<токен>.ics` (по умолчанию выключена): календарь телефона сам перечитывает адрес, подсказка
    просит обновлять раз в час. Каждое событие на весь день со стабильным UID, поэтому перенесённый срок
    переезжает, а не дублируется. «Новый адрес» меняет токен, старый адрес перестаёт работать. iPhone подписывается
    сам (`webcal://`), на Android нужно приложение ICSx⁵: Google Календарь не видит домашний сервер.
- **Лента.** Все фото прогресса по дням, свежие сверху, фильтр по проекту. Клик открывает фото на весь экран с подписью
  (проект, дата, стадия, заметка) и листанием стрелками. Переключатель «Фото / Журнал» (запоминается в браузере):
  **Журнал** (`activity.py`) показывает по дням, что происходило с проектами: создание, смена статуса и стадии,
  новые задачи, смена статуса и срока задачи, удаление и восстановление, отпуск. Время, проект (клик открывает
  карточку) и пометка «через бота» для действий из Telegram. Фильтр по проекту, по 200 событий, «Показать ещё».
  События пишутся в одном месте, перед записью в базу, поэтому одинаково ловятся из веба, бота и шаблонов.
  Не пишутся: задачи, закрытые вместе с проектом, сроки, сдвинутые отпуском (вместо них одно событие «Отпуск»),
  переименования, заметки, фото и приоритет. При первом запуске журнал восстанавливает прошлое по датам
  завершения проектов и задач (с пометкой «восстановлено по дате», без времени).
- **Зал Славы и аналитика.** Четыре показателя (завершено проектов, закрыто задач, заработано токенов, общий прогресс
  задач), график воронки стадий для активных проектов, график закрытых задач и проектов за 6 месяцев, архив
  завершённых проектов (награда, число задач, дата финиша, заметки, кнопка «Вернуть в работу»), у архива
  свой поиск с теми же правилами; при вводе графики не перерисовываются.

### Карточка проекта в списке
Фото слева, справа название, бейджи (награда, приоритет, значок 📝 если есть заметки, 🖼 N — число референсов,
счётчики закрытых и открытых задач) и дедлайн: «Горит!» при остатке до 3 дней, «Просрочено» после даты.
Внизу выпадающие списки статуса и стадии. Кнопки: открыть в новой вкладке и удалить (с диалогом подтверждения).

- **Клик по фото:** если фото нет, открывается выбор файла; если есть — фото раскрывается на весь экран.
- **Перетаскивание:** картинку можно перетащить на фото проекта (заменяет обложку), на блок референсов или на блок прогресса (несколько файлов сразу). Пока файл тащат над окном, все зоны подсвечиваются.
- **Вставка из буфера (Ctrl+V):** картинка уходит в блок под курсором (обложка, референсы, прогресс; на дашборде — обложка карточки под курсором). Если курсор не над блоком, а карточка открыта, приложение спрашивает, куда вставить. Вставка текста работает как обычно.
- **Клик по названию или бейджам** открывает карточку проекта.

### Открытая карточка проекта
- Шапка: фото (смена и удаление), название с карандашом (название и приоритет; в DEV MODE ещё дедлайн),
  кнопка «в новой вкладке», «Шаблон пайплайна», «+ Задача».
- **Подвкладки** (только в компактной карточке поверх дашборда): «Задачи» — заметки и задачии,
  «Фото» — референсы и прогресс (рядом с названием число картинок). Открытая подвкладка сохраняется, пока
  карточка открыта; при открытии другого проекта снова «Задачи». В отдельной вкладке (`/?card=`) подвкладок нет.
- **Заметки по проекту** (рецепты красок, идеи, что угодно): сохраняются автоматически при выходе из поля и по кнопке «Сохранить».
- **Референсы покраса:** до 20 картинок (JPEG, PNG, WebP, GIF до 25 МБ). Оригиналы сохраняются без изменений,
  для сетки браузер делает маленькие превью. Просмотр на весь экран со стрелками. Порядок меняется перетаскиванием плиток
  (на компьютере), он сохраняется и используется в просмотре.
- **Прогресс:** лента времени из фото проекта (слева старые, справа новые). Каждое фото хранит дату и стадию, которая была
  у проекта в момент загрузки, плюс необязательную подпись (видна под снимком, правится кнопкой ✎ или кликом по ней). До 10 файлов за раз; браузер уменьшает фото до 1600 px (JPEG),
  крестик на снимке удаляет его. Метка TG на снимке означает, что фото пришло из Telegram.
- **Задачи:** статус (выпадающий список), редактирование, удаление.
- **Шаблон пайплайна:** кнопка открывает окно из двух шагов. Шаг 1 — выбор шаблона (список из настроек, у каждого
  число этапов и их названия), шаг 2 — сроки этапов. Шаблоны редактируются в Настройки → Шаблоны (см. ниже).
  По умолчанию их два:
  - **3D-печать**, 7 этапов: поддержки и печать, промывка и засветка, шлифовка и шпаклёвка, сверловка под штифты,
    грунт и прешейдинг, базовый покрас аэрографом, детализация и лак.
  - **Сборная модель**, 5 этапов: снятие с литника и зачистка, склейка и шпаклёвка стыков, грунт и прешейдинг,
    базовый покрас, детализация и лак.
  - **Окно сроков (шаг 2):** у каждого этапа своя дата (по умолчанию срок проекта) и галочка «создавать».
    Этап без галочки не создаётся, пустая дата — задача без срока. Ссылка «Распределить равномерно» раскладывает
    даты включённых этапов от сегодня до срока проекта (если срок уже в прошлом, всем ставится срок проекта).
  - **Повторное применение** не создаёт дубли. Этапы, которые уже есть среди задач проекта, в окне помечены
    «уже есть» и не создаются; если есть все, кнопка «Создать этапы» неактивна. Сравнение по названию без номера
    в начале и без учёта регистра, поэтому узнаются и задачи из старых шаблонов («3. Склейка…»). Этапы
    встроенных шаблонов, которые не правили, узнаются на любом языке интерфейса; свои и исправленные этапы —
    по тексту как есть. Общие этапы разных шаблонов (грунт, покрас, детализация) тоже не повторяются.
  - Задачи создаются **без номеров** в названии (номера видны только в окне шаблона): своя задача или удалённый
    этап не сбивают нумерацию.
  - API: `GET /api/pipeline-templates?project_id=<id>` отдаёт `{"templates": [{"id", "name", "steps": [названия на
    языке интерфейса], "raw": {исходные значения}}], "defaults": [встроенные], "existing": {id: [номера этапов,
    которые уже есть в проекте]}, "custom": шаблоны_изменены}`. `POST /api/projects/{id}/template`
    принимает `{"kind": "<id шаблона>", "steps": [{"index": 0, "deadline": "2027-03-21"}, ...]}`. Без `steps`
    создаются все этапы со сроком проекта, без тела запроса работает как `print`. Неверный номер этапа, повтор,
    дата не в формате `YYYY-MM-DD` или пустой список дают ошибку, в базу ничего не пишется. Ответ содержит
    `added` и `skipped` (сколько этапов создано и сколько пропущено как уже существующие); если все выбранные
    этапы уже есть, возвращается ошибка.
- **Даты** в интерфейсе, боте и уведомлениях всегда с годом. Формат выбирается в Настройки → Общие:
  `dmy` — `21.03.2027` (по умолчанию, для любого языка), `mdy` — `03/21/2027`. Поля ввода даты в окнах
  тоже следуют настройке (`static/dateinput.js`): родное `<input type="date">` браузер показывает в формате
  своего языка, поэтому рядом с ним ставится текстовое поле в формате приложения с кнопкой календаря.
  Дату можно набрать цифрами (разделители подставляются сами) или выбрать в системном календаре; неверная
  дата при уходе с поля откатывается к прежней. Значение по-прежнему хранится в родном поле в ISO
  (`2026-10-31`), поэтому остальной код читает и пишет `.value` как раньше.

### Правила задач
- Нельзя создать задачу без описания; пробелы по краям обрезаются, длина до 300 символов.
- Задача создаётся только в существующем проекте вне корзины.
- Для проектов не в статусе «В планах» дедлайн задачи обязателен; если он не указан, а у проекта есть дата, берётся она.
- Даты принимаются только в формате `YYYY-MM-DD`; неверная дата даёт понятную ошибку, а не сбой сервера.
- Ошибки сервера (пустое имя, проект не найден, неверное значение) показываются всплывающим сообщением.

### Обновление данных и ввод
- Страница перечитывает данные после каждого действия и при возврате фокуса в окно. Если запросы пересеклись,
  применяется только самый свежий ответ.
- Текст, который сейчас набирается в заметках, при таком обновлении не затирается: поле обновляется,
  только когда в нём нет несохранённых правок.

### Фото
Фото проекта (обложка) браузер сжимает до 1400 px и сохраняет как JPEG (максимум 6 МБ). Формат проверяется на сервере
по содержимому файла, имя файла генерируется сервером.

### Прочее
- **Карточка в отдельной вкладке:** адрес `/?card=<id>` показывает только карточку проекта, на всю ширину страницы:
  на широком экране слева заметки и задачи, справа референсы и фото прогресса крупными превью (стили в `static/card-tab.css`).
- **Обновление данных** при возврате фокуса в окно (не чаще раза в 3 секунды), поэтому несколько вкладок не расходятся.
- **Клавиши:** Esc закрывает верхнее окно, Enter подтверждает форму, в просмотре картинок — стрелки.
- **Корзина.** Кнопка «🗑 Корзина (N)» рядом с поиском (видна, когда в корзине что-то есть): окно со списком, сколько дней
  осталось, кнопки «Вернуть», «Стереть» и «Очистить корзину».
- **Подтверждения удаления** показываются диалогом в стиле интерфейса.
- **Телефон.** На экране уже 640 px (`static/mobile.css`) вкладки становятся нижней панелью, шапка — двухстрочной
  (не липнет к верху), строки задач складываются в столбик, окна почти во весь экран. Кнопки, видимые по наведению
  мыши, на сенсорных экранах показаны всегда. На iPhone поля ввода 16 px, чтобы Safari не увеличивал страницу.
- **PWA.** Манифест и иконки позволяют добавить страницу на главный экран; блок «Приложение на телефоне» в
  Настройки → Основные показывает кнопку «Установить» (Chrome, событие `beforeinstallprompt`) или подсказку для
  браузера. Service worker (только на доверенном HTTPS или `localhost`): страницы и `/static/*` — сначала сеть,
  без сети страница заменяется заглушкой `static/offline.html`; Tailwind, Chart.js и шрифты — локальные файлы
  (`static/vendor/`, `static/fonts/`), CDN не используется;
  `/api/*` и `/photos/*` не кэшируются. После правок `sw.js` нужно увеличить `VERSION`.
- **Темы:** «Стандарт», Cyberpunk, Warhammer 40k, SCP Dossier, Workbench, Synthwave, JRPG (FFVII), Model Manual,
  Hardware PCB. Выбор хранится в браузере (`localStorage`, ключ `ph_skin`),
  кнопки и окна оформлены под каждую тему. Темы перечислены в реестре `THEMES` (`static/app.js`).
  **Графики** следуют теме: цвета столбцов, сетки, подписей, шрифт и скругление берутся из CSS-переменных `--chart-*`
  активной темы и перерисовываются сразу при её смене. Как добавить свою тему, описано в `THEMES_GUIDE.md`;
  проверка: `python tools/check_theme.py [имя]`.

### Окно настроек
Семь разделов: **Основные** (DEV MODE, цена проекта, поведение при удалении, сроки в календарь телефона, язык), **Уведомления** (отпуск, перенос,
детектор застоя, пятничный план, ежемесячный отчёт, проверка связи), **Расписание** (по дням недели), **Шаблоны**
(шаблоны пайплайна), **Бэкап** (автобэкап и занятое место), **Telegram** (привязка чата, уборка сводок, необязательный прокси, справка «Что умеет бот» с теми же текстами, что `/help`), **Доступ** (вход по паролю, смена пароля, выход).

**Шаблоны пайплайна** (`pipeline.py`, `static/templates.js`). Хранятся в `config.json` (`PIPELINE_TEMPLATES`); пока
ключа нет, действуют два встроенных. В редакторе можно переименовать шаблон, добавить, удалить, переставить и
переименовать этапы, завести свой шаблон или удалить любой, в том числе встроенный (должен остаться хотя бы один).
«Сбросить к стандартным» возвращает два встроенных. Изменения сохраняются общей кнопкой «Сохранить». Ограничения:
до 20 шаблонов, до 30 этапов, название шаблона до 60 символов, этапа до 120; пустые этапы отбрасываются.
У встроенных шаблонов название и этапы хранятся ключами перевода (`template.print`, `pipeline.print.step1`...) и
переводятся при смене языка; строка, которую поправили, сохраняется обычным текстом. Если сохранённый список совпал
со встроенным, ключ из конфига убирается. Задачи, уже созданные по шаблону, правка шаблона не меняет.
`POST /api/pipeline-templates` принимает `{"templates": [{"id", "name", "steps": [...]}]}` или `{"reset": true}`.

**Отпуск** (`vacation.py`, Настройки → Уведомления). Поле «Дней» (1–30) и кнопка «Уйти в отпуск» с подтверждением.
Действует сразу, без кнопки «Сохранить»:
- сроки всех незавершённых проектов вне корзины (в том числе на паузе) и их незавершённых задач сдвигаются на N дней;
  задачи без срока, завершённые проекты и задачи не меняются;
- «последнее движение» этих проектов тоже сдвигается, поэтому детектор застоя не считает отпуск простоем;
- автоматические пуши (вечерняя сводка, пятничный план, отчёт за месяц) не отправляются до конца отпуска;
  тестовый пуш и бот работают как обычно;
- в шапке появляется плашка «Отпуск до …» (клик открывает настройки уведомлений).
«Прервать отпуск» сразу возвращает уведомления, сроки остаются сдвинутыми. Пока отпуск идёт, новый начать нельзя.
В `config.json`: `VACATION` = `{"start", "until", "days"}`; `until` — первый день после отпуска.
API: `POST /api/vacation` (`{"days": N}`), `POST /api/vacation/cancel`; состояние приходит в `GET /api/data`
(`vacation`: `active`, `start`, `until`, `days`).

## 5. Telegram-бот

Работает через long polling. Запросы идут в рабочем потоке с жёстким таймаутом, напрямую или через прокси
(см. «Прокси» ниже). Одно HTTP-соединение переиспользуется между запросами (без нового TCP/TLS/SOCKS-рукопожатия на каждый
вызов); оно пересоздаётся при смене прокси и при плановом переподключении: каждые 3 часа и примерно за 10 минут до
ближайшего запуска пушей по расписанию.
- Смещение `getUpdates` сохраняется между сессиями, поэтому после переподключения последние нажатия не приходят повторно.
- После сетевой ошибки (нет связи, прокси отказал) бот ждёт 3 секунды, а не повторяет запрос в цикле.
- Ошибка в одном апдейте не мешает обработке остальных; токен бота вырезается из текста ошибок в журнале.
- Сборка карточек и списков из базы выполняется в рабочем потоке и не задерживает веб-интерфейс.

### Прокси (необязательно)
Нужен, только если Telegram недоступен напрямую (`tgproxy.py`, Настройки → Telegram → «Прокси для Telegram»).
- **Откуда берётся адрес.** Если блок в интерфейсе ни разу не сохраняли, действует `PROXY_URL` из `.env`, как раньше
  (пусто — напрямую). После «Применить» действует только настройка из интерфейса (`config.json`, `TG_PROXY` =
  `{"enabled", "url"}`): выключено — напрямую, даже если `PROXY_URL` в `.env` заполнен.
- **Без перезапуска.** Адрес читается при каждом запросе бота и при каждой рассылке, переключение срабатывает со
  следующего запроса. В журнале при старте сессии видно, как бот подключается: «напрямую» или «через прокси …».
- **Форматы:** `socks5://`, `socks5h://` (DNS через прокси), `http://`, `https://`, логин и пароль в адресе
  допустимы. MTProto-прокси (`tg://proxy?…`, секреты `dd…`) для Bot API не подходят и отклоняются.
- **Пароль не уходит в браузер:** интерфейс получает только маску (`socks5://***@host:1080`). Пустое поле при
  «Применить» оставляет сохранённый адрес (или адрес из `.env`, он тогда копируется в `config.json`).
- **«Проверить связь»** делает запрос `getMe` с тем, что сейчас в форме (до сохранения), и показывает имя бота или ошибку.
- API: `GET /api/telegram/proxy` (состояние: `source` = `env` или `settings`, `enabled`, `has_url`, `display`),
  `POST /api/telegram/proxy` (`{"enabled", "url"}`), `POST /api/telegram/proxy/check` (те же поля).
Весь пользовательский текст экранируется перед отправкой (режим HTML).

### Привязка к чату
- Бот отвечает **только привязанному чату** (`TG_CHAT_ID` в `config.json`). Сообщения и нажатия кнопок от других
  чатов игнорируются, запись в журнал не чаще раза в час.
- Пока чат не привязан, бот принимает только `/start КОД` из **личного** чата. Код одноразовый (8 символов вида
  `K7M2-X9QP`), показывается в Настройки → Telegram и в журнале при старте.
- После пяти неверных кодов за 10 минут попытки привязки блокируются.
- Кнопка «Отвязать чат» удаляет привязку и создаёт новый код. «Новый код» меняет код, пока чат не привязан.

### Команды

| Команда | Что делает |
|---|---|
| `/start` | приветствие и список команд |
| `/current_task` | проект в фокусе: статус, стадия, приоритет, награда, баланс, задачи с кнопками |
| `/projects` | все активные проекты с кнопками перехода |
| `/help` | команды и возможности бота; список берётся из реестра `COMMANDS` и `FEATURES` в `bot.py`, оттуда же строится меню «/» в Telegram |
| `/task [название]` | конструктор задачи: проект, название, срок (кнопки «Сегодня», «Завтра», «Через 3 дня», «Через неделю», «Срок проекта», «Своя дата», «Без срока»); дату можно написать в формате из настроек |
| `/photo` | последнее фото прогресса по всем проектам; кнопки ◀ ▶ листают, «Удалить» спрашивает подтверждение |
| `/myphotos` | выбрать проект (в списке только те, где есть фото или референсы, завершённые тоже), затем «Прогресс» или «Референсы» |
| `/calendar` | сроки файлом `.ics`: открыть на телефоне, и они добавятся в календарь. Только при включённой выгрузке в календарь, иначе команды нет в меню и `/help` |
| `/clear` | очистить чат: спрашивает «Удалить всё (N)» или «Всё, кроме последней сводки», потом «Чат очищен», которое само исчезает через 5 секунд |
| `/stats` | статистика текущего месяца: закрытые задачи, завершённые проекты, заработанные токены, баланс |
| `/test_notify` | запускает тестовое уведомление |

**Проект в фокусе:** среди активных сначала «В работе», затем по приоритету (Critical → Low), затем по ближайшему
дедлайну. Под карточкой — блок «Горящие задачи по другим проектам» (до 3 дней или просрочено, проекты на паузе не
учитываются).

### Конструктор задач в боте
`/task` или кнопка «➕ Задача» (в карточке проекта и в списке проектов). Если активный проект один или кнопка нажата в
карточке, шаг выбора проекта пропускается; название можно дать сразу: `/task Грунтовка плаща`. Срок обязателен у проектов не
«в планах» (как в веб-интерфейсе), «Без срока» показывается только для «в планах». Дата своя: `21.03.2027` или `03/21/2027`
по настройке, год можно опустить (берётся ближайшая будущая дата). Любая команда отменяет начатую задачу, черновик хранится
в памяти один час. Новые возможности бота нужно вписывать в реестр `COMMANDS` или `FEATURES`, тогда `/help` обновится сама.

### Фото в боте
- **Отправить фото боту** (как фото или как файл-картинку, до 20 МБ). Подпись к фото становится заметкой. Если активный
  проект один, фото сохраняется сразу; если несколько, бот спрашивает кнопками, к какому проекту оно относится
  (есть «Отмена»). Подборка из нескольких фото получает один вопрос. После сохранения кнопки «Фото проекта» и «Отменить»
  (удаляет только что сохранённые фото).
- **Если фото не сохранилось**, бот всегда об этом пишет: «Фото не добавлено» с причиной, а для подборки «Не добавлено
  фото: N из M». Это касается и фото из подборки, пришедших после ответа, и вопроса «к какому проекту», который уже
  отменён или устарел, и любой неожиданной ошибки при обработке.
- **Просмотр фото прогресса.** `/photo`, `/myphotos` → проект → «Прогресс» или кнопка «Фото (N)» в карточке проекта.
  Листание идёт в том же сообщении (`editMessageMedia`), порядок от новых к старым. У фото одного проекта есть кнопка
  «Назад» к выбору типа.
- **Просмотр референсов.** `/myphotos` → проект → «Референсы» или кнопка «Референсы (N)» в карточке проекта. Порядок как
  в карточке, ◀ ▶ листают. JPEG и PNG до 5 МБ уходят как есть, остальные показываются уменьшенной копией;
  «📎 Оригинал» присылает файл без сжатия документом. Добавлять и удалять референсы через бота нельзя, только в приложении.
- Ожидающие ответа фото хранятся в памяти один час; после перезапуска бота вопрос «к какому проекту» устаревает,
  и фото нужно отправить заново.

### Уборка чата (`tgclean.py`)
Telegram разрешает боту удалять сообщения только младше 48 часов, а историю чата бот читать не может. Поэтому бот
записывает каждое отправленное и полученное сообщение (`tg_messages`) и удаляет только их; то, что было до появления
уборки, он не знает.
- **`/clear`** удаляет всё известное младше 48 часов: свои сообщения, твои команды и фото, сводки. Можно оставить
  последнюю сводку. Удаление идёт пачками по 100 (`deleteMessages`).
- **Уборка сводок** (`TG_CLEANUP`, Настройки → Telegram), проверка каждые 10 минут:
  - «Хранить 46 часов» (по умолчанию): старые сводки удаляются в 46 часов, последняя остаётся всегда;
  - «Только последняя»: новая сводка убирает предыдущие;
  - «Не удалять».
  Сводки — это сообщения `notify.py` (вечерняя сводка, пятничный план, тест пуша); ежемесячный отчёт не удаляется.
  Если бот был выключен в окне 46–48 часов, сводка остаётся навсегда.

### Кнопки
«В работу» и «Готово» у задачи, «Сменить стадию» (меню стадий), «Все активные проекты», переходы между проектами.

**«📤 Поделиться»** в карточке проекта присылает альбом для пересылки: обложка, 5 последних фото прогресса и референсы
(всего до 10, предел Telegram), в подписи название, стадия и заметки. Задачи, токены и сроки не попадают.
Длинные заметки приходят отдельным сообщением; большие оригиналы (больше 5 МБ), GIF и WebP уходят превью.
Пересланный альбом не даёт доступа к данным: бот отвечает только привязанному чату.
Из пуша: закрыть задачу и «+2д» — **перенос дедлайна**: дата сдвигается на 2 дня от большей из двух дат
(текущий дедлайн или сегодня). Если перенос выключен в настройках (`allow_postpone`), кнопка из старого пуша отвечает,
что перенос выключен; закрытую задачу перенести нельзя, повторное «закрыть» не меняет дату закрытия.
Переносить можно повторно, но начиная со второго раза бот отвечает ехидным
комментарием, который становится злее с каждым переносом (2-й, 3-й, 4-й, 5-й и дальше). Это только текст: токены
не списываются. В карточке бота у задачи стоит ⏳ (или ⏳×N), в пуше счётчик ⏳×N показывается со второго переноса.

## 6. Уведомления

`notify.py` отправляет в привязанный чат одно сообщение за запуск:

1. **Просрочено** и **Горит (до 3 дней)**: незавершённые задачи с дедлайном в проектах, которые не закончены и не на
   паузе, от самых просроченных к ближайшим. Задачи без дедлайна не попадают. Под сообщением до 4 кнопок «закрыть»
   и «+2д» для самых срочных задач.
2. **Детектор застоя:** проекты «В работе», по которым нет движения `stagnation_days` дней (по умолчанию 10).
3. **Пятничный план** (по пятницам): до трёх незавершённых задач каждого проекта «В работе», ближайшие по сроку, и
   отдельным списком проекты «В работе» без единой открытой задачи (им нечего планировать).
4. **Отчёт за прошлый месяц** отправляется 1-го числа (если включён) перед вечерней сводкой.
5. Если сказать нечего, приходит «Всё по плану!» с текущим фокусом.

В DEV MODE и во время отпуска (см. «Окно настроек») автоматические пуши пропускаются.

**Защита от дублей.** Автоматическая рассылка выполняется не чаще раза в 10 минут: запуск занимает «слот» в
`.notify_state.json` под файловой блокировкой, поэтому одновременные запуски (старый cron плюс планировщик, два
экземпляра приложения) дают одно сообщение. Блокировка работает и в Linux (`fcntl`), и в Windows (`msvcrt`).
Пропущенный запуск пишет в `logs/notify.log`, кто занял слот. Флаги:
`--test` (тест, обходит защиту), `--force` (обходит защиту), `--monthly` (только отчёт), `--source=имя`.
Код выхода 0 — сообщение отправлено (или отправлять было нечего), 1 — Telegram не принял сообщение или нет токена;
код виден в `logs/notify.log`.

## 7. Планировщик

- Проверяет расписание каждые 20 секунд, каждая задача запускается не чаще раза в минуту.
- **Пуши настраиваются отдельно для каждого дня недели:** флажок и время (24 часа). Общий переключатель отключает
  все пуши сразу. Кнопка «Время Пн → всем дням» копирует время.
- **Бэкап:** ежедневно в заданное время, если включён.
- Расписание хранится в `config.json` (`SCHEDULE`), старый формат «будни и выходные» мигрирует автоматически.
- **Догон после простоя.** Планировщик отмечает «приложение работает» в `scheduler_state.json` (раз в 5 минут и
  при каждом запуске задачи). При старте он смотрит, какие запуски пришлись на время простоя, и выполняет
  последний пропущенный запуск каждой задачи (через 15 секунд после старта, когда поднялись веб и бот):
  - пуши: только если с планового времени прошло не больше 3 часов и это тот же календарный день (вечерняя
    сводка ночью уже не нужна);
  - бэкап: если прошло не больше 24 часов.
  Задача, которая уже выполнялась, не повторяется. Первый запуск (нет файла состояния) ничего не догоняет.
  Смена расписания в работающем приложении догон не вызывает: время «уже прошло», но простоя не было.
- Уже выполняющаяся задача повторно не запускается.

## 8. Бэкап

`backup.py` отправляет JSON (`projects`, `tasks`, `timestamp`) на Google Apps Script по адресу `APPS_SCRIPT_URL`
(редиректы поддерживаются). Код выхода 1, если адрес не задан или Google ответил ошибкой (видно в `logs/backup.log`).
В копию попадают проекты и задачи. **Фото, референсы и корректировки баланса в копию
не входят**: папку `photos/` и файл `tracker.db` нужно копировать отдельно. База работает в режиме WAL, рядом с
`tracker.db` появляются `tracker.db-wal` и `tracker.db-shm`. Копировать файл на ходу нельзя (свежие записи лежат
в `-wal`): остановите приложение или сделайте копию командой `sqlite3 tracker.db ".backup копия.db"`.

**Занятое место** (Настройки → Бэкап, `storage.py`, `GET /api/storage`). Считается при открытии раздела и по кнопке
«Обновить» обходом папок, без внешних команд. Строки: файлы приложения (всё в папке приложения, кроме данных ниже),
база (`tracker.db` с `-wal`/`-shm`), фото (обложки, референсы, фото прогресса), журналы (`logs/` и старые `*.log`
в корне). Если есть, отдельно показываются копии базы из `tools/deploy.sh` (`backups/`), `.venv` и `.git`.
Размер — длина файлов, а не место, выделенное на диске; свободное место на диске пока не показывается.

## 9. Локализация

- Языки: русский (`ru-RU`) и английский (`en-US`). Язык выбирается в Настройках и действует везде: интерфейс, бот,
  уведомления и сообщения сервера. После смены языка страница перезагружается, даты в интерфейсе форматируются
  по выбранной локали.
- **Один файл `locales.json`**, внутри блоки по кодам языков:

  ```json
  {
    "ru-RU": { "meta.name": "Русский", "common.save": "Сохранить", "ref.limit": "Лимит: максимум {n} референсов на проект" },
    "en-US": { "meta.name": "English", "common.save": "Save",      "ref.limit": "Limit: at most {n} references per project" }
  }
  ```

- **Ключи технические**, вида `область.имя` (`common.save`, `settings.tab.backup`, `err.project_not_found`,
  `bot.task_closed`). Русская фраза в коде больше не нужна: чтобы поправить формулировку, достаточно изменить
  значение в `locales.json`, код и шаблоны не трогаются. Области: `common`, `nav`, `analytics`, `stats`, `project`,
  `task`, `deadline`, `confirm`, `photo`, `ref`, `recipe`, `toast`, `err`, `settings`, `tg`, `bot`, `notify`,
  `status`, `stage`, `day`, `pipeline`, `theme`, `hall`, `meta`.
- Где используется:
  - Python (сервер, бот, уведомления): `tr("common.save")`, `tr("ref.limit", n=10)`.
  - Шаблоны: `{{ tr('common.save') }}`. Текст подставляется на сервере, вспышки неперевёденного текста нет.
  - JavaScript: `tr('common.save')`, `tr('ref.limit', {n: 10})`. Словарь выбранного языка сервер кладёт в страницу
    (`window.APP_I18N`).
- **Запасные варианты:** нет ключа в выбранном языке — берётся `ru-RU`, нет и там — показывается сам ключ.
  Ошибка в подстановке (`{n}` не передан) приложение не роняет.
- Названия проектов и задач никогда не переводятся. Статусы, стадии и дни недели в базе остаются каноническими
  русскими значениями (`В работе`, `Покрас`, `Пн`...), чтобы не ломать данные и `callback_data` бота; для показа их
  переводит `tv(значение)` (таблица `VALUE_KEYS` в `i18n.py`). Названия шагов шаблона пайплайна подставляются на
  языке, выбранном в момент нажатия, и дальше хранятся как обычный текст задачи.
- **Новый язык:** добавьте блок с кодом и ключом `meta.name` в `locales.json`, он сразу появится в списке.
  Заготовка со всеми ключами: `python tools/check_locales.py --create de-DE --name Deutsch`.
- **Новый текст:** придумайте ключ, добавьте его в `ru-RU` и `en-US`, используйте в коде.
- **Проверка:** `python tools/check_locales.py`. Ищет ключи, которых нет в одном из языков, расхождения `{подстановок}`,
  «текст вместо ключа» в вызовах `tr()` и неиспользуемые ключи; `--fix` дописывает недостающие и сортирует файл.

## 10. Конфигурация

**`config.json`**

| Ключ | Значение |
|---|---|
| `DEV_MODE` | тихий режим, редактирование, проекты без токенов |
| `INITIAL_TOKENS`, `PROJECT_COST` | стартовый баланс и цена проекта |
| `DELETE_KEEPS_BALANCE` | удаление проекта не меняет баланс |
| `TRASH_DAYS` | сколько дней проект лежит в корзине до стирания (1-3650, по умолчанию 30) |
| `LANGUAGE` | код языка из `locales.json`: `ru-RU`, `en-US` (старые `ru`/`en` переносятся сами) |
| `DATE_FORMAT` | формат дат: `dmy` (по умолчанию) или `mdy`; неизвестное значение сбрасывается в `dmy` |
| `NOTIFY` | `allow_postpone`, `stagnation_alert`, `stagnation_days`, `friday_digest`, `monthly_report` |
| `SCHEDULE` | `notify_enabled`, `notify_days` (по дням: `enabled`, `time`), `backup_enabled`, `backup_time` |
| `PIPELINE_TEMPLATES` | шаблоны пайплайна (нет ключа — два встроенных), редактируются в Настройки → Шаблоны |
| `VACATION` | отпуск: `start`, `until` (первый день после отпуска), `days` |
| `TG_CLEANUP` | уборка сводок в чате бота: `keep_46h` (по умолчанию), `latest_only`, `off` |
| `TG_PROXY` | прокси для Telegram из интерфейса: `enabled`, `url` (нет ключа — берётся `PROXY_URL` из `.env`) |
| `CALENDAR_EXPORT` | выгрузка сроков на устройства: кнопка «В телефон», файл `.ics`, `/calendar` и подписка (по умолчанию `false`; вкладка «Календарь» от неё не зависит) |
| `ICS_FEED` | подписка на календарь: `enabled`, `token` (секретная часть адреса `/cal/<токен>.ics`) |
| `TG_CHAT_ID`, `TG_PAIRING_CODE` | привязка бота (служебные) |

Файл записывается атомарно (временный файл и `os.replace`), недостающие ключи подставляются значениями по умолчанию.
Прочитанный конфиг кэшируется и перечитывается, только когда файл на диске изменился (время, размер, inode), поэтому
изменения из другого процесса (`notify.py`) и правки руками подхватываются без перезапуска. Если `config.json` испорчен
(не JSON), он переименовывается в `config.json.broken-<время>`, приложение запускается с настройками по умолчанию и
пишет об этом в журнал; привязку бота и настройки можно вернуть из сохранённой копии.

**`.env`:** `TELEGRAM_BOT_TOKEN`, `PROXY_URL` (необязательно; используется, пока прокси не настроен в интерфейсе), `APPS_SCRIPT_URL`.

## 11. HTTP API

Ответы вида `{"status": "ok"}` или `{"status": "error", "message": "..."}`; сообщения приходят на языке интерфейса.

| Метод и путь | Назначение |
|---|---|
| `GET /` | страница (язык и словарь встроены в разметку) |
| `GET /login` | страница входа (когда вход включён) |
| `GET /sw.js`, `/manifest.webmanifest` | service worker и манифест PWA (без входа) |
| `POST /api/auth/login`, `/logout` | вход (логин + digest пароля) и выход |
| `GET /api/auth/status` | вход включён ли, имя пользователя, нужна ли смена пароля |
| `POST /api/auth/change`, `/enable` | сменить пароль; включить или выключить вход (выключение требует пароль) |
| `GET /api/data` | проекты, задачи, баланс, настройки, расписание, языки |
| `POST /api/config` | сохранить настройки (проверка формата времени и языка) |
| `POST /api/notify/test` | запустить тестовое уведомление |
| `GET /api/calendar.ics` | сроки файлом `.ics` (скачивание) |
| `GET`, `POST /api/calendar/feed` | состояние подписки; включить или выключить (`enabled`), заменить адрес (`new_token`) |
| `GET /cal/<токен>.ics` | подписка на сроки; без входа по паролю, неверный токен или выключенная подписка дают 404 |
| `GET /api/activity` | журнал: `project` (фильтр), `offset`; по 200 событий, `more` — есть ли ещё |
| `GET /api/storage` | занятое место по категориям (байты и число файлов) |
| `GET /api/telegram` | состояние привязки: привязан ли чат, ID чата или код привязки |
| `POST /api/telegram/unlink`, `/api/telegram/code` | отвязать чат; создать новый код |
| `GET`, `POST /api/telegram/proxy`, `POST /api/telegram/proxy/check` | прокси для Telegram: состояние (без пароля), сохранить, проверить связь |
| `POST /api/action` | смена статуса и стадии проекта, статуса задачи |
| `POST /api/projects` | создать проект |
| `POST /api/projects/{id}/edit`, `/rename` | редактировать с дедлайном (DEV MODE); название и приоритет (всегда) |
| `POST`, `DELETE /api/projects/{id}/photo` | загрузить и удалить фото |
| `POST /api/projects/{id}/refs`, `DELETE …/refs/{ref_id}` | добавить и удалить референс |
| `POST /api/projects/{id}/refs/order` | новый порядок референсов (`ids` — полный список по порядку) |
| `DELETE /api/projects/{id}` | убрать проект в корзину |
| `POST /api/projects/{id}/restore`, `DELETE /api/trash/{id}`, `DELETE /api/trash` | вернуть из корзины, стереть насовсем, очистить корзину |
| `POST /api/projects/{id}/progress`, `PATCH`, `DELETE …/progress/{photo_id}` | добавить фото прогресса (`image`, `thumb`, `note`), изменить подпись, удалить |
| `POST /api/projects/{id}/notes`, `/template` | заметки по проекту; шаблон пайплайна (`kind`: id шаблона, необязательные `steps` со сроками) |
| `GET`, `POST /api/pipeline-templates` | шаблоны на языке интерфейса (с `project_id` — какие этапы уже есть в проекте); сохранить или сбросить шаблоны |
| `POST /api/vacation`, `/api/vacation/cancel` | начать отпуск на N дней (1–30); прервать отпуск |
| `POST /api/tasks`, `/api/tasks/{id}/edit`, `DELETE /api/tasks/{id}` | задачи |

`POST /api/action` принимает только известные значения: статусы проекта `В планах`, `В работе`, `На паузе`, `Закончен`;
стадии из списка выше; статусы задачи `Не начато`, `В процессе`, `Закончен`. Другое значение даёт ошибку. Приоритет
проекта — `Low`, `Medium`, `High`, `Critical`, награда и цена проекта не меньше 0.

Обработчики, которые работают с базой и файлами, выполняются в пуле потоков FastAPI, поэтому медленная SD-карта или
долгий запрос не останавливают бота и планировщик, работающих в том же процессе.

Загрузки передаются JSON-ом с base64, без отдельных библиотек для multipart. Изображения проверяются по содержимому
(JPEG, PNG, GIF, WebP), типы SVG и подмена расширения отклоняются.

## 12. Безопасность

- **Вход по паролю необязателен и по умолчанию выключен** (Настройки → Доступ). Пока он выключен, веб-интерфейс
  открыт всем, кто видит порт 8000. Рассчитан на домашнюю сеть или VPN.
- **Как устроен вход** (личный вариант, один пользователь):
  - Логин по умолчанию `admin`, пароль `123456`. Пока пароль не сменён, закрыто всё, кроме смены пароля и выхода.
    Новый пароль не короче 8 символов (проверка в браузере, на сервер приходит только digest).
  - Пароль уходит не открытым текстом: браузер шлёт `SHA-256("project-hub:<логин>:<пароль>")`, сервер хранит
    `scrypt(digest, соль)` в `auth.json`. Это защищает от случайного подсмотра и от повторного использования пароля
    на других сайтах. **Без HTTPS перехваченный digest можно переслать повторно**, поэтому для сети лучше включить
    HTTPS (см. «HTTPS» ниже).
  - Сессия: подписанная cookie (`HttpOnly`, `SameSite=Lax`, `Secure` при https), срок 14 дней. Подпись привязана
    к паролю: смена пароля сбрасывает все сессии.
  - Перебор: 5 ошибок с одного адреса за 5 минут блокируют вход на остаток окна, каждая ошибка даёт паузу.
  - Закрыто всё, включая `/photos`; открыты только `/login`, `/api/auth/login`, `/static/`, `/sw.js` и
    `/manifest.webmanifest` (без последних двух не работает установка PWA), а также `/cal/` — подписка на календарь:
    календарь телефона не умеет входить по паролю, поэтому паролем служит длинный токен в адресе.
  - Проверка пароля (scrypt) выполняется в рабочем потоке и не задерживает остальные запросы.
  - Бот Telegram, уведомления и планировщик работают мимо веба, вход их не затрагивает.
  - **Забыли пароль:** `python auth.py reset` (сбросит на `admin`/`123456` и выключит вход);
    `python auth.py status` показывает состояние.
- **HTTPS** (`tls.py`, по умолчанию выключен):
  - `HTTPS=1` в `.env` включает TLS на том же порту (`PORT`, по умолчанию 8000). `app.py` при старте берёт параметры
    из `tls.uvicorn_options()`; ошибка настройки останавливает запуск понятным сообщением.
  - Сертификат: если `SSL_CERTFILE` и `SSL_KEYFILE` не заданы, при первом запуске создаются `certs/server.crt` и
    `certs/server.key` (RSA 2048, SHA-256, 825 дней, ключ с правами 600) командой `openssl`. В `subjectAltName` входят
    `localhost`, `127.0.0.1`, имя хоста и `имя.local`, адреса хоста в сети и всё из `TLS_NAMES`. Сменился адрес:
    `python tls.py cert --force`. Осталось меньше 30 дней: предупреждение при запуске; истёк: запуск отказывается.
  - Свой сертификат (mkcert, Let's Encrypt): задать оба пути в `.env`, тогда ничего не создаётся.
  - Cookie сессии получает флаг `Secure` сама (`auth.py` смотрит на схему запроса и на `X-Forwarded-Proto`).
    Если перед приложением стоит обратный прокси (Caddy, nginx), TLS можно оставить ему, а `HTTPS` не включать.
  - Во вкладке «Доступ» показывается, по какому соединению открыта страница (по `location.protocol`).
- **Бот** привязан к одному чату, привязка только по одноразовому коду из личного чата, с защитой от перебора.
- Секреты хранятся в `.env`; в `config.json` лежат только ID чата и код привязки (и адрес прокси, если его задали в
  интерфейсе). Токен бота вырезается из текста ошибок перед записью в журнал.
- Пользовательский текст экранируется в вебе и в сообщениях Telegram; словарь переводов встраивается в страницу
  без возможности выйти за пределы `<script>`.
- Загрузки: ограничения по размеру, проверка формата по содержимому, имена файлов генерирует сервер.

## 13. Эксплуатация

- **Запуск:** `python app.py` (uvicorn, `0.0.0.0:8000`); в текущей установке — systemd-сервис `tracker.service`.
- **Логи:** `logs/app.log` (бот, планировщик, ошибки), `logs/notify.log`, `logs/backup.log`; у каждого три копии `.1`-`.3` по 1 МБ.
- **Что копировать при переезде или обновлении:** `tracker.db`, `photos/`, `config.json`, `auth.json`, `.env`.
- **Обновление:** `tools/deploy.sh [ветка]` (копия базы, `git fetch`, зависимости, перезапуск, проверка; `--rollback`
  возвращает прошлую версию) или вручную: заменить файлы приложения и перезапустить сервис. Схема базы мигрирует сама.
- **Если cron остался:** строки с `notify.py` и `backup.py` из crontab нужно убрать, расписание теперь внутри приложения.

## 14. Известные ограничения

- Вход по паролю: один пользователь, без ролей и прав. По HTTP перехват digest возможен (см. раздел «Безопасность»).
- HTTPS выключен по умолчанию, сертификат самоподписанный (предупреждение браузера на каждом устройстве), продления нет, перенаправления с HTTP нет.
- Бэкап в Google Sheets не включает фото, референсы и фото прогресса.
- PWA без доверенного HTTPS: только ярлык на экране, без service worker.
- Приём фото в Telegram проверен только на подмене Telegram API, на живом боте нужно проверить один раз.
- Названия этапов правятся в Настройки → Шаблоны, в окне сроков только даты и галочки. Названия задач сохраняются на языке, активном при создании.
- Отпуск хранит только последний период. Прерванный отпуск сроки не возвращает (так задумано).
- Догон пропущенных запусков ограничен окном (3 часа для пушей, 24 часа для бэкапа) и берёт только последний запуск.
- DEV MODE объединяет три функции в одном переключателе.
- Статусы и стадии хранятся русскими строками, список стадий задан в коде.
- База SQLite без внешних ключей. Режим WAL включён, но на файловой системе без его поддержки (сетевые диски)
  база работает в обычном режиме, об этом приложение пишет в журнал.
